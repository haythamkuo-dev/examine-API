# AI 協作與變更規範

## 目標

本專案使用 React 與 TypeScript 建立全端產品。AI 的角色是協助盤點影響、提出可驗證的實作方案、完成已確認的變更與檢查結果，不取代產品、商業規則、安全性或架構決策。

任何變更都以可審查、可回復、可驗證為原則。不得因為實作方便而新增未確認的功能、資料欄位、端點、權限、狀態或重構。

## 變更前的必要輸入

開始前，先明確記錄：

- 目標：要改善的使用情境，以及完成後可觀察的行為。
- 非目標：本次刻意不處理的流程、介面、資料修復或重構。
- 已知限制：相容性、權限、安全性、部署順序、回復方式與時程。
- 依據：需求、issue、設計決議、既有程式碼、API 契約與資料模型。

資訊不足時，AI 必須先列出問題，並說明每個問題會影響的功能、資料、契約或測試。假設必須標示為假設，不得寫成已確認行為。

## 先盤點，後修改

修改程式前，應先讀取適用的專案規範與相鄰程式碼，並盤點影響面：

- 前端：路由、頁面、元件、狀態管理、表單、API 呼叫、錯誤與載入狀態。
- 後端：路由、認證與授權、輸入驗證、服務層、外部整合、錯誤映射與設定。
- 共用契約：請求與回應型別、schema、錯誤碼、版本相容性與 SDK。
- 資料層：資料擁有者、schema、migration、索引、constraint、交易、回填與回復。
- 品質：單元、整合與端對端測試，文件與觀測性。

涉及跨層、公開契約、權限、資料模型或部署流程時，不能只從單一檔案推論設計。應找出引用點、現有契約與相關測試，再決定實作範圍。

## 設計分流

小型且局部的變更，應先提供簡式設計說明：目標、非目標、影響檔案、核心行為、驗證方式與風險。

符合任一情況時，必須先取得完整設計確認，再開始實作：

- 新增或改變公開 API、請求或回應 schema、錯誤碼或相容性行為。
- 新增或改變登入、權限、付款、個人資料或其他安全邊界。
- 新增資料庫、修改 schema、執行 migration、回填或清理資料。
- 改變跨服務流程、外部整合、背景任務、部署或 rollback 策略。
- 有兩種以上合理解法，且取捨會影響產品、成本、效能或後續維護。

完整設計至少包括目標與非目標、現況與影響面、已確認行為、待決策事項、方案比較、資料與契約變更、部署與回復、驗證策略及不可開始實作的阻塞點。

## 已確認內容與待決策事項

正文只能描述已有依據且已確認的行為。未確認的需求、商業規則、權限判斷、資料保留策略與 API 語意，必須獨立列在「待決策事項」或「方案比較」。

發現需求、程式碼、測試、API 文件或資料模型互相矛盾時，應列出衝突與影響，不得自行選擇其中一方作為真相來源。

## 前後端與契約邊界

- 前端不得直接存取資料庫或持有伺服器端秘密。
- 後端負責認證、授權、輸入驗證、商業規則與資料存取控制。前端驗證只能改善體驗，不能取代後端驗證。
- 公開輸入必須在執行期驗證，TypeScript 型別不可視為不可信輸入的驗證機制。
- API 的欄位、必填條件、null 語意、錯誤碼與版本相容性必須明確定義。變更前先列出現有消費者與遷移策略。
- 共用型別應由明確的契約來源產生或集中維護，避免前端與後端各自複製語意。

## 資料庫演進規範

資料庫加入後，schema 與 migration 視為正式公開的系統行為。

- 每項資料變更要說明資料擁有者、用途、敏感等級、保留策略與讀寫路徑。
- migration 必須可在乾淨資料庫與既有資料庫執行，並有明確的驗證與回復策略。
- 線上環境優先採取「先擴充、再遷移、最後收斂」：先新增可相容結構，部署雙讀寫或回填，確認消費端完成遷移後才移除舊結構。
- 不得在未確認資料影響、備份與回復方案下刪除欄位、資料表或大量資料。
- 唯一性、外鍵、非空、預設值、索引與交易邊界，必須依業務不變式設計，不得只因 ORM 預設而省略判斷。
- 回填工作須具備範圍、批次策略、可重跑性、進度監測與失敗處置。不得把大量回填隱含在一般部署流程。
- 涉及個人資料或敏感資料時，必須先確認最小蒐集、存取權限、遮罩、刪除與稽核需求。

## 實作與驗證

實作前，AI 應先說明計畫與待確認事項。實作後，應回報實際改動、未處理項目與驗證證據。

完成不以「程式可編譯」為準，而以核心行為與風險都已驗證為準。測試至少應覆蓋成功路徑、輸入錯誤、授權失敗、關鍵邊界條件與資料一致性。若變更涉及資料庫或跨服務流程，還應驗證 migration、失敗處置與回復路徑。

若測試未能執行、驗證不足或存在未解決的關鍵決策，AI 必須明確標示，且不得宣稱變更已完成。

## 每次 AI 協作的輸出格式

1. 已知事實與來源。
2. 目標、非目標與完成定義。
3. 影響面盤點。
4. 待決策事項與阻塞點。
5. 實作計畫或已完成的變更。
6. 驗證結果、風險與後續建議。
